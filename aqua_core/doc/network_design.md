# 网络设计：控制面与数据面

Aqua 有两个逻辑通道：**控制面**（gRPC over TCP：会话生命周期、参数下发、存活探活）与**数据面**（UDP：音频与
Heartbeat 保活）。本文定义两者的**地址与地址族设计** —— 绑定什么、通告什么、由谁决定用哪一族，以及这些决定
换来哪些不变量。

模块级实现细节在 `modules/`：`udp.md`（UdpServer/UdpClient）、`udp_transport.md`（socket 与收发机器）、
`grpc.md`（控制面 RPC 与通告）、`session.md`（会话与族粘性）、`address.md`（族判定与地址工具）、
`runtime.md`（两侧 runtime 的装配与失败语义）。参数默认值只有一处权威来源：`configuration_reference.md`。

## 1. 分层结论

|                    | 控制面                                        | 数据面                                |
|--------------------|-----------------------------------------------|---------------------------------------|
| 绑定                | 单一地址（`--rpc-ip`）                        | **逐族**（`--udp-ipv4` / `--udp-ipv6`） |
| socket 数           | 1（族行为由 gRPC 实现决定，不可配置）         | **每族一条**，严格单族                |
| 服务族集合          | 通配绑定时由 gRPC 决定（实测见 §5.4）         | 由绑定结果显式决定，可逐族独立开关    |
| 端口                | `--rpc-port`                                  | `--udp-port`（两族共用）              |
| 谁决定客户端用哪族  | 客户端（它用哪个地址连上的控制面就是它的族）  | ——                                    |
| 通告                | 下发**按客户端族分槽**的数据面端点（§3）      | ——                                    |

一句话：**控制面只需要"有一个可达地址就能 bootstrap"，数据面才需要"族可控"。** 因此"v4 与 v6 独立工作"这条
需求落在数据面；要求控制面也做到既不可实现、也没有必要（§8、§9）。

## 2. 数据面：一 socket 一族

### 2.1 两条 socket，v6 那条保持 `v6_only=true`

数据面每族一条独立 socket：v4 是 `AF_INET`，v6 是 `AF_INET6` **且显式 `v6_only=true`**。这不是细节，而是
整个设计的前提：

- 它让"两族共用同一个端口"成立 —— 否则两条 socket 抢同一端口会 `EADDRINUSE`；
- 它让 `::ffff:a.b.c.d` 这种表示**从不进入系统**：绑 `0.0.0.0` 只接受原生 IPv4 来源、绑 `::` 只接受原生
  IPv6 来源，于是 session endpoint、日志、诊断、C API 暴露的地址永远只有一种形态。

单 socket 双栈（关掉 `v6_only`）能省一条 socket，但代价是日志与 session 身份里遍地 `::ffff:`，而且**无法
再表达"只服务 v6"** —— 一个 `0.0.0.0` 会同时接受 IPv6 来源。这个取舍已被明确否决，不在选项内。

### 2.2 绑定策略与失败语义

| 配置                        | 语义                                                   |
|-----------------------------|--------------------------------------------------------|
| `--udp-ipv4 0.0.0.0`（默认）| 监听所有 IPv4 接口；下发通配 sentinel（§3.1）          |
| `--udp-ipv4 192.168.1.5`    | 只在该接口服务（多网卡用户指定某个局域网）             |
| `--udp-ipv4 none`           | 关闭 IPv4 数据面 ⇒ 该族槽不存在，该族客户端连接期被拒  |
| `--udp-ipv6 ::`（默认）     | 监听所有 IPv6 接口；下发通配 sentinel                  |
| `--udp-ipv6 fdfd::1`        | 只在该地址服务                                         |
| `--udp-ipv6 none`           | 关闭 IPv6 数据面                                       |

失败语义按"这个地址是用户显式要求的还是默认的"区分：

- **pin 了具体地址而绑定失败 ⇒ 启动失败**（响亮，不静默换地址）；
- **默认通配而绑定失败**（例如机器禁用 IPv6）⇒ 该族降级不可用 + warning，另一族照常服务；
- **任一族的 receive 启动失败 ⇒ 整体回滚**：一条"绑上了但收不到"的 socket 是最难诊断的状态。

两族都被关闭（`none` + `none`）会在启动期被拒绝 —— 没有数据面的 server 没有意义。

### 2.3 扇出按会话的族路由

服务端广播不是 IP 广播/组播，而是**按会话逐个单播**：一份编码好的 datagram 共享发给每个已 Connected 的
session。发的时候必须用**该 session 的族**对应的那条 socket，这是正确性而不是优化：

- 在 `AF_INET6` socket 上用 `AF_INET` 目标 `send_to` 直接 `EAFNOSUPPORT`；
- 反过来，换一条 socket 回包会打破 NAT 映射（映射绑定在 (本地端口, 远端端口, 协议族) 上），音频静默丢失。

实现见 `modules/udp.md`。

## 3. 通告：按客户端族分槽

### 3.1 槽的三态

控制面下发的是**两个槽**：`udp`（给 IPv4 客户端）与 `udp6`（给 IPv6 客户端）。每个槽有三种状态：

| 槽状态              | wire 上的样子                     | 含义                                       | 客户端行为                       |
|---------------------|-----------------------------------|--------------------------------------------|----------------------------------|
| 具体地址            | 字段在，`address` 是具体字面量    | 拨它                                       | 直接用该地址                     |
| 通配 sentinel       | 字段在，`address` 是 `0.0.0.0`/`::`| "用你自己连控制面时用的那个地址"           | 回落到自己的 `--rpc-ip`          |
| **字段不存在（空槽）** | `has_udp()` / `has_udp6()` 为假 | **本 server 不服务该族数据面**             | 硬失败并回滚已建 session         |

用**字段存在性**而不是"空串 + port 0"编码空槽是刻意的：后者是歧义编码（`address="" + port=50000` 到底算不算
sentinel？），存在性没有歧义。客户端另有一层冗余护栏：`port == 0` 或空地址一律视为无效槽。

槽值只在"绑定地址是通配且没有显式 `--udp-advertise-*`"时才是 sentinel —— 也就是说，**sentinel 的族由槽保证**，
客户端拿到的永远是自己族能用的地址。

注意这条纪律现在也排除了另一种回落：绑定**带 zone** 时下发的是剥掉 zone 的具体地址，而不是
sentinel（sentinel 只在通配绑定下安全，见 §5.3 的展开）。也就是说"sentinel 可达"依赖的不只是
族，还有"socket 收所有接口"这个前提。

### 3.2 客户端如何选槽

客户端按**自己的族**选槽：v4 读 `udp`，v6 读 `udp6`。它不需要问任何人自己的族 —— `--rpc-ip` 必须是一个具体
IP 字面量（不通配、不解析 DNS），所以**客户端族在配置期就唯一确定**。

选中之后还有一道自证：槽内地址必须是**本族原生形态**，否则 Connect 失败。跨族地址意味着两侧配置或版本不一致，
应当响亮失败，而不是把音频发向一个跨族目标后静默丢包。默认情况下 client 不做"换个端点再试"的候选回退 ——
槽是服务端按族给的，回退只会在错误的地方制造第二个权威。

### 3.3 族准入：控制面可达族 ⊆ 数据面服务族

**能通过控制面连上的客户端，其所在族必须是数据面服务的那一族。** 这条关系不是审美偏好：客户端"能用 v4 连上
控制面 ⇒ v4 也能打到数据面"是它自己的默认假设（sentinel 回落就是这条假设的实例）。

违反它的后果是设计里最坏的一种：**客户端连得上、拿得到 session、然后 3 秒内收不到任何 ACK 而退出**，两侧日志
都只说"没收到 ACK"，真因（族不匹配）零可诊断性。

因此在 Connect 期做准入检查：服务端从 `ctx->peer()` 取出客户端族，若该族的数据面未被服务，**在创建 session
之前**返回 `FAILED_PRECONDITION` 与可操作消息。两个边界条件：

- **peer 族解析不出来时不拒绝**（fail-open）：解析失败不得误拒合法客户端，漏判由客户端侧的空槽硬失败兜住；
- 这条检查是**防御性**的：主机制是"槽的存在性 = 该族是否被服务"（§7 INV-7）。
- **例外：`--rpc-ip` pin 到具体地址时，"由构造成立"不成立。** 通配绑定下 gRPC 自带双栈（可达族 = 两族），
  "可达族 ⊆ 服务族"由槽的存在性保证；但 pin 到具体地址后可达族收窄为该地址的族，它**可能不在**服务族里。
  **修复前**的实测形态：`--rpc-ip ::1 --udp-ipv6 none`（控制面只 v6、数据面只 v4）**照常启动**，随后每个客户端
  都在 Connect 期被拒（客户端 `FAILED_PRECONDITION` 点名族、服务端 warn）；反向 `--rpc-ip 127.0.0.1` + 默认数据面
  则是 v6 socket 空转且**无任何告警**。因此现在由启动期显式校验守住（`runtime::check_control_plane_coverage()`，
  见 `modules/runtime.md`）：bind 之前用请求的服务族拒绝 `可达 ∩ 服务 == ∅` 的组合，bind 之后用实际
  绑定结果复核并 warn/debug。

### 3.4 为什么不由服务端猜 peer 族来选地址

"服务端判一下客户端是哪个族、只返回那一个 advertise 地址"是一个自然的想法，但被否掉了：

- **猜不准**：`ctx->peer()` 是控制面对端的文本形态，双栈监听下 v4 客户端会显示成 `::ffff:`，要额外归一化；
  advertise 地址还可能是 NAT/多网段地址，按族推不出"另一个族的对外地址"；
- **猜错没有退路**：协议里只有一个值时，客户端拿到的端点不可用就只能失败 —— 没有备选可试；
- **客户端本来就知道**：它刚刚用某个地址连上了控制面，这是免费的 happy-eyeballs 结果。

因此协议下发的是**两个槽**而不是"服务端替客户端选好的一个值"。

## 4. 会话与 NAT

### 4.1 族粘性

session 记录**族**（由收到 datagram 的那条 socket 写入，不从地址反推）。首包建连时钉住族；此后同一 session_id
的 heartbeat 若从另一族到达，一律拒绝。理由是回包只可能从其中一条 socket 发出，而 endpoint 会在两条 socket
之间横跳。**换族 = 重连 = 新 session**，与既有"重连即新会话"的模型一致。

### 4.2 NAT 落点

会话的 UDP endpoint 的唯一写入者是**收到这个包的那条 socket**，回包（HeartbeatAck 与音频）必须走同一条。
这正是不需要任何特殊 NAT 机制的原因：NAT 映射绑定在 (本地端口, 远端端口, 协议族) 上，只要"谁收到谁回"这条
不变量成立，映射就自动正确。

反面做法是把 endpoint 收进一张全局表然后统一用一条 socket 发 —— 那会在有 NAT 的部署里静默丢音频。

### 4.3 端口转发与跨网段 advertise

`--udp-advertise-ipv4` / `--udp-advertise-ipv6` / `--udp-advertise-port` 表达的是"**我本地怎么绑 ≠ 你该往哪打**"，
用于 NAT、容器、端口转发、多网段等部署：advertise 可以指向与绑定地址**同族的另一个网段**的地址，而客户端对此
无感。

约束（都是启动期校验，不是运行期风险）：advertise 必须是对应族的**具体**地址、必须与绑定地址**同族**、v6 不得
携带 zone id（§5.3）。跨族通告不被支持 —— 它会让"槽 = 客户端族"这条关系失去意义。

## 5. 地址形态的分层规则

### 5.1 `effective_family` 与 `is_native_family` 不能混用

这是本设计里最容易踩的一处，两个函数看着像、用途完全不同：

```text
effective_family(addr)      归一化后的族：::ffff:a.b.c.d → V4
                            用途：分类 —— 会话/诊断的族标签、客户端族判定、gRPC peer 文本
is_native_family(addr, f)   地址的**文本形态**是否属于该族的原生形态（v4-mapped 两边都不算）
                            用途：任何会把地址**原样交给套接字层**的地方
```

用错的方向只有一个但很隐蔽：拿 `effective_family` 去做"交给套接字层"的判定，会让 `::ffff:a.b.c.d` 通过校验、
随后开出一条 `AF_INET6` socket —— 文本是 v6、语义是 v4，两边都不像。失败形态与 §3.3 描述的一样：不报错，
几秒后以"收不到 ACK"暴露。

**判定清单**（这些入口必须用 `is_native_family`）：服务端数据面绑定、通告地址、控制面绑定；客户端拨号目标、
选中的槽地址、单族 bind 适配器；以及最底层 `UdpTransport::bind()` / `set_remote()` —— 它是"地址交给套接字层"的
最后一道关口，因此自己也要拒绝，不依赖上层。

`normalize_for_display()` 只用于日志/诊断/UI：它的返回值**不能**用来替换"用于发送的存储 endpoint"。

### 5.2 交给套接字层的地址必须原生

推论：**任何把地址文本原样交给套接字层的入口都要做原生形态校验**，且校验要下沉到最底层那一层。
一个只靠"上层都校验过了"的设计会在新增调用方时静默失效。

### 5.3 link-local 与 zone id

`fe80::/10` 是链路本地地址，`::1` 是回环 —— 前者带 zone（Windows 用接口索引 `%24`，Linux/Android 用接口名
`%wlan0` 或索引），后者没有。zone 是**逐主机本地的接口索引**，只对"从哪块网卡发出去"有意义。由此三条规则：

```text
wire 上永不携带 zone      --udp-advertise-ipv6 里出现 '%' 直接拒绝（配置错误应响亮失败）；
                           服务端绑定带 zone 时，下发的是**剥掉 zone 的具体绑定地址**
client 自己补 zone        复用它连控制面时 --rpc-ip 里的 zone；两端都缺 zone 就报明确错误
server 绑 link-local 要带自己的 zone   不带会被内核 EINVAL 拒绝；
                           但**默认的 :: 通配也能正常收答 link-local 流量**，
```

**为什么带 zone 的绑定要"剥 zone 下发具体地址"而不是回落成通配 sentinel**

sentinel 的语义是"用你自己连控制面时用的地址"，它成立的前提是**数据面通配绑定**——socket 收
所有接口，客户端拿自己的地址过来一定到。只有通配绑定才允许回落 sentinel（见 §3.1 的
"槽值是通配且没有显式 --udp-advertise-*"）。

绑定是具体的（link-local 钉某块网卡、或带 zone 的全局地址）时，回落 sentinel 就变成"把客户端
自己的地址塞给一个只收另一个地址的 socket"，而且全程无告警：

```text
server --rpc-ip 2001:db8::5 --udp-ipv6 fe80::1%24      # 多网卡：控制面走以太，数据面钉 link-local
client --rpc-ip 2001:db8::5
  ⇒ 槽值 :: ⇒ 客户端拨 2001:db8::5:50000
  ⇒ 服务端 v6 socket 绑在 fe80::1%24，内核丢弃
  ⇒ gRPC 通、session 建、心跳无人回 ⇒ 3 次 miss 后 Degraded
```

剥掉 zone 下发 `fe80::1` 正好落在"client 自己补 zone"这条已有机制上：客户端借 `--rpc-ip`
的 zone 补回来；借不到（控制面是全局地址、与数据面不同网卡）时它**响亮失败**——把静默丢失
变成明确的连接错误，这比 sentinel 好。

单机做回环测试时 zone 天然一致，所以"本机测通了"不代表跨机可用；跨机时发方必须用**自己**的 zone。

### 5.4 gRPC 的族行为与 peer 文本（实测）

- **监听**：gRPC 只要绑定通配地址（`0.0.0.0` 或 `::`），就会在**两族**上监听（`netstat` 可见同 PID 的
  `0.0.0.0:PORT` 与 `[::]:PORT`）。这是实现行为而不是文档契约，也没有运行时开关 —— 它不表达"只服务 v6"。
  因此**控制面的服务族集合是不可配置的**（§8）。
- **peer 文本**：`ctx->peer()` 是 URI 编码形态，**方括号本身也被编码**：

  ```text
  ipv4:127.0.0.1:58307          ← 字面形态
  ipv6:%5B::1%5D:58382          ← 实测！%5B=[ %5D=]（不是字面的 "[::1]"）
  ipv6:%5B::ffff:1.2.3.4%5D:p   ← 双栈监听下的 v4 客户端
  ipv6:%5Bfe80::1%2524%5D:p     ← zone 的 '%' 编码成 %25
  ```

  解析必须先对主机部分做**一次** percent-decode 再做结构解析（只解一次：`%25` → `%` 是 zone 的正确编码，
  二次解码会把它变成垃圾）。这条例子的教训值得记住：**任何解析外部生成文本的代码，都要先用真实样本取样再写测试**，
  否则测试用的会是臆想形态，全绿而功能静默失效。契约与测试见 `modules/address.md`。

### 5.5 本机 IPv6 地址形态（部署提醒）

一台多网卡 Windows 机器上通常同时存在五类 IPv6 地址：link-local（每个接口一个）、ULA（`fd00::/8`）、稳定 GUA、
**临时 GUA**（隐私扩展，会轮换）。两条运维结论：

- **不要 pin、也不要 advertise 临时 GUA**：它轮换的那一刻会静默失联，而 `ipconfig` 里它与稳定地址挨着显示，很容易抄错；
- **通配绑定会把端口开到所有接口**，包括 VPN/虚拟网卡（如代理软件的 TUN 设备）。多网卡主机应显式 pin；
  这条同时写进 `security_and_deployment.md`。

功能测试优先用 ULA/GUA（无 zone、不需要路由器）；link-local 的独有价值在于"**没有 IPv6 路由器的链路上它依然存在**"，
属于产品能力而不是测试便利。

## 6. 配置面总览

三组参数，职责互不重叠：

```text
rpc-*                  --rpc-ip / --rpc-port                 控制面（单一绑定）
udp-ipv4 / udp-ipv6    --udp-ipv4 / --udp-ipv6 / --udp-port  数据面（逐族绑定 + 共用端口）
udp-advertise-*        --udp-advertise-ipv4 / -ipv6 / -port  通告（"通知客户端往哪打"）
```

- 默认值让**无参数启动即两族都能用**（`--rpc-ip 0.0.0.0`、`--udp-ipv4 0.0.0.0`、`--udp-ipv6 ::`、单端口）；
- `--rpc-ip` **只**决定控制面。它曾同时喂给数据面，那会让"我只想限制控制面"变成"数据面也被限制"这种隐式耦合；
- `--udp-ipv4 192.168.1.5 --udp-ipv6 fdfd::1` 即"两族各绑一个具体地址"（多网卡场景）；
- 校验在 CLI 与 Core **各做一次**：Core 是公共入口，不依赖 CLI 是否拦过。

## 7. 不变量

```text
INV-1   一 socket 一族：v6 socket 保持 v6_only=true ⇒ ::ffff: 永不进入系统
INV-2   NAT 落点：会话 endpoint 由收到它的那条 socket 写入；ACK 与音频只从同一条回
INV-3   族粘性：首包钉族；跨族 heartbeat 被拒（换族 = 重连 = 新 session）
INV-4   通告按客户端族分槽（udp / udp6）；空槽 = 不服务；通配 = sentinel（族由槽保证）
INV-5   pin 严格（绑定失败即启动失败）、默认宽松（该族降级 + warn）
INV-6   逐族独立：绑定 / 通告 / 诊断 / 统计都可分别观察与控制
INV-7   槽存在 ⟺ 该族数据面绑定成功。由它推出的"控制面可达族 ⊆ 数据面服务族"**只在
        `--rpc-ip` 通配时由构造成立**；pin 具体地址时可达族收窄，由启动期校验守住（见 §3.3）
INV-8   客户端族在配置期唯一确定（`rpc_ip` 必须是具体字面量 —— 由 Core 的
        `ClientRuntime::start()` 校验，覆盖 CLI 与 C API/JNI 两条路径）
INV-9   任何交给套接字层的地址必须是该族的原生形态（判定用 is_native_family）
INV-10  wire 上永不携带 zone id（zone 是逐主机本地的，不跨主机）
INV-11  单端口：两族数据面共用 --udp-port（INV-1 是它能成立的前提）
```

## 8. 被否决的方案

| 方案 | 做法 | 否决理由 |
|---|---|---|
| 单 socket 双栈（"通配即双栈"） | 只把通配绑定的 socket 关掉 `v6_only` | `0.0.0.0` 会同时接受 IPv6（v4-mapped）来源，`::ffff:` 进入日志与 session 身份，且无法再表达"只服务某族" |
| 服务端猜 peer 族后返回单值通告 | 服务端判族、只下发一个 advertise 地址 | 猜不准（peer 文本需归一化、advertise 可能是 NAT 地址）；猜错没有退路（协议里没有备选） |
| `repeated udp_endpoints` 候选列表 + 客户端逐个试 | 下发列表，客户端按序尝试并锁第一个成功 | 客户端要承担"换端点重建 transport + 有界等待 ACK"的复杂度；而"按族分槽"用槽的存在性就把同一件事做得更强 |
| 向 gRPC 对齐（让控制面也只服务一族） | 期望 gRPC 提供 v6-only 开关 | 不可实现：gRPC 每个 v6 socket 都无条件关掉 `IPV6_V6ONLY`，没有运行时开关（§5.4） |
| 不做双栈、只做"诚实报错" | 保留单族数据面，Connect 期拒绝不匹配的族 | 能兑现"可诊断"，但不能兑现"默认两族都能用"这条产品需求 |

## 9. 控制面传输：保留 gRPC

地址族问题**不是**剥离 gRPC 的理由：数据面的族不可控来自"单 socket + 单值通告"，与 gRPC 无关；而 gRPC 的通配
双栈恰恰是"只有 v4 的客户端也能连上绑 `::` 的 server"的原因 —— 那正是白送的资产（§5.4）。

要剥离的真实理由是**重量**：控制面只有 4 类消息、≤1KB、约 1 QPS、局域网、无加密需求，gRPC 对它是约两个数量级的
过度供给（HTTP/2 + abseil + protobuf runtime，还要静态链进库、拖慢构建、多一套 NDK 交叉编译）。

如果将来要做，形态建议是**纯 TCP + protobuf 消息**（`--cpp_out` 而不生成 gRPC 桩），不要用 KCP：1 QPS 的小消息
用不到重传/拥塞控制，而且它会占 UDP 端口、与数据面的端口语义和 NAT 故事纠缠。
必须复刻的既有语义：每个 RPC 都有 deadline；keepalive 区分"连续传输 miss"（容抖）与 `session_valid=false`
（确定性结论，立即上报）；在途 RPC 可取消；Connect 响应构造失败要回滚 session；shutdown 阻塞至在途 handler 结束；
`connect_to_server` 失败不得留下旧 stub。这些细节见 `modules/grpc.md`。

**当前结论：不剥离。** 这项属于独立的重量议题，与地址族无关。
